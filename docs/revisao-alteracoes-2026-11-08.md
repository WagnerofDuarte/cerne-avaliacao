## ABSTRACT

- **ALTERADO**
  - antes: Coding agents based on large language models have increased the autonomy of software development, but there is little empirical evidence for choosing among spec-driven development methodologies that organize the work of these agents. This work compares two of them: GitHub Spec Kit, which drives a single agent through incremental commands, and BMAD-METHOD, which plans the product up front and splits the work among specialized agents. In a comparative case study, the same developer applied each methodology in sequence, with the same agent (Claude Code with the Claude Sonnet 5 model), to build the same mobile journaling app, Cerne, decomposed into eleven work units. The protocol, the measurement instrument and the deviation log were defined before execution, and process metrics were collected from the raw session transcripts. A total of 274 sessions were analyzed. Spec Kit consumed 25.9 hours of active time, 4.9 million output tokens and the equivalent of US$ 271 in cost; BMAD-METHOD consumed 82.7 hours, 9.1 million output tokens and the equivalent of US$ 902, that is, 3.2, 1.9 and 3.3 times more, respectively. In the paired analysis by requirement, BMAD-METHOD required more time in all nine pairs (Wilcoxon signed-rank test, exact p = 0.004), but triggered fewer corrective interventions by the researcher (16 versus 49), at the price of more answers to pauses foreseen by the proces
